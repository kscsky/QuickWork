---
title: ゾーン間ハンドオフ
description: カードをこのワークスペースから別のワークスペースへ送り、受領を戻します。
---

ハンドオフルールは**この**ワークスペースのあるステータスを監視します。カードがその
ステータスに入ると、QuickWork は別のワークスペースにタスクを作成し、そのワークス
ペースのエージェントを起動します。対象カードが受領ステータスに達すると、このカードに
通知されます。

**境界を越えるのは仕事であって、カードではありません。** 元のカードはここに残り、
自分のステータス・担当者・履歴を保ちます。実際に流れるのは、ルールから作られた新しい
タスクと、持ち出すことを選んだコンテキストです。

## ルールの置き場所

ルールは**送信側**ワークスペースに属し、その設定から管理します。各ワークスペースは
自分が何を送るかだけを決め、何を受け取るかは決めません。

保存時に検証されるのは**送信先側**で、しかも自分のアカウントではなく**リレートークン**を
使います。実際に配信を行うのはこのトークンなので、トークンが実行できないルールは、
記入中に拒否されます——本物のカードが初めてそれを発火させたときに静かに失敗するのでは
ありません。

## ルールを構成するもの

| フィールド | 何を決めるか |
| --- | --- |
| ルール名 | ルール一覧のラベル。他には何も読みません。 |
| トリガーステータス | **このワークスペース**でハンドオフを発火させるステータス。 |
| 送信先ワークスペース | 仕事の送り先。 |
| 送信先エージェント | そのワークスペースでタスクを引き受けるエージェント。 |
| ハンドオフメモ | 任意。対象タスクに付加される追加指示。 |
| 受領ステータス | **対象**カード上の、このカードへ報告するステータス。 |

## どのカードが発火するか

既定ではルールは**レーン単位**です。トリガーステータスに入る**すべての**カードが
発火します。常設のパイプラインにはこれが正しい形です——「準備完了にしたものは全部
ビルドゾーンへ」。

範囲が広すぎる場合は、特定のタスクを選びます。選んだタスクだけが発火し、同じ
ステータスに入る他のカードは影響を受けません。3 枚だけ送りたいのであって、レーンを
開きたいわけではないときに使います。

## 受領の区間

ハンドオフは投げっぱなしではありません。対象カードが受領ステータスに達すると、元の
カードに通知されます。このワークスペースを見ている人は、別のワークスペースへ切り替えて
確認しなくても、仕事が終わったことが分かります。

受領ステータスは**対象**カード上のステータスであり、このカードのものではありません。
それが往復を完結させます。誰も到達しない受領ステータスを設定したルールは、仕事を
届けても決して報告しません。
