---
title: 跨区交付
description: 把卡片从这个工作区路由到另一个，并把回执带回来。
---

一条交付规则盯着**本**工作区的一个状态。卡片进入该状态时，QuickWork 会在另一个
工作区建一个任务，并唤醒那个工作区的智能体。目标任务到达回执状态时，本卡片会
收到通知。

**跨过去的是活，不是卡片本身。** 源卡片留在本区，保留自己的状态、负责人和历史。
真正流转出去的，是按规则新建的任务，加上你选择带过去的上下文。

## 规则存放在哪

规则属于**源**工作区，在源工作区的设置里管理。每个工作区只管自己往外发什么，
不管别人往里送什么。

保存时校验的是**目标侧**，而且用的是**中继令牌**，不是你的账号。中继令牌才是真正
执行投递的身份——所以令牌执行不了的规则会在你还在填表时就被拒绝，而不是等到第一张
真实卡片触发它时才悄悄失败。

## 一条规则由什么组成

| 字段 | 它决定什么 |
| --- | --- |
| 规则名称 | 规则列表里的标签，别的什么都不读它。 |
| 触发状态 | **本工作区**里触发交付的那个状态。 |
| 目标工作区 | 活送到哪里去。 |
| 目标智能体 | 目标工作区里接手这个任务的智能体。 |
| 交付备注 | 可选，附加到目标任务上的额外说明。 |
| 回执状态 | **目标**卡片上的那个状态，用来回报本卡片。 |

## 决定哪些卡片会触发

默认情况下规则是**车道级**的：**任何**进入触发状态的卡片都会触发。这对常设流水线
是对的——"只要我们标成就送到构建区"。

如果这个范围太宽，就改成指定任务：只有你选中的任务会触发，其他进入同一状态的卡片
不受影响。你只想把三张特定的卡片推过去、而不是开一条车道时，用这个。

## 回执那一段

交付不是发出去就不管了。目标任务到达回执状态时，源卡片会收到通知——盯着本工作区
的人不必切到另一个工作区去确认，就能看到活干完了。

回执状态是**目标**卡片上的状态，不是本卡片的，它是这个来回的收尾。如果一条规则配了
一个永远到不了的回执状态，活会送达，但永远不会有回报。
